# Human-review coordinator preflight

Complete this checklist before inviting reviewers or sending a packet. It is
an operational safeguard, not a substitute for your university's
research-ethics rules.

- [x] Ask the research guide whether this reviewer exercise needs an ethics
      committee/IRB determination, consent-language approval, or departmental
      permission before recruitment. Record the decision privately.
- [ ] Pilot the frozen packet yourself only for timing and usability. Do not
      create eligibility labels or inspect SafeMAP outcomes during the pilot.
- [ ] Put the exact function count and a realistic time range in the reviewer
      invitation. State whether breaks or multiple sessions are expected.
- [ ] Decide where private consent/contact records will be stored, who can
      access them, and when they will be deleted. Do not commit them to Git.
- [x] Assign unrelated pseudonymous IDs. Keep the identity-to-ID map separate
      from review responses.
- [x] Screen prior exposure and conflicts consistently for both reviewers.
- [x] Send identical packet hashes, codebook versions, instructions, and
      deadlines to both reviewers.
- [ ] Answer procedural questions without suggesting labels. Record any
      clarification sent to one reviewer and send the same clarification to the
      other.
- [x] Hash each returned CSV and JSON immediately. Freeze both original files
      before opening adjudication.
- [x] Do not publish held-out tool outcomes or either reviewer's judgments until
      both independent reviews are complete.
